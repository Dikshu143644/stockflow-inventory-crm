# Multi-branch management, barcode scanning, mobile polish, and QA infrastructure (v1)

Phase 8 delivers four features in one pass: a branch CRUD system with a global branch selector, a camera-based barcode scanner with product lookup, PWA/mobile-responsive improvements, and a Vitest test harness with 22 passing tests. However, neither BranchesPage nor BranchSelector actually connects to the database - both render hardcoded mock data, making the branch feature a UI shell that will silently ignore real Supabase data. The service worker uses a stale-while-revalidate pattern for static assets but has no versioning strategy tied to Vite's content-hashed filenames, which will cause cache staleness across deployments.

Watch for: BranchSelector uses a hardcoded branch list instead of the `useBranches` hook (confirmed); BranchesPage CRUD operations are no-ops against mock data (confirmed); service worker caches Vite's hashed assets without a cache-bust mechanism on deploy (likely); search filter in `useBranches` interpolates user input directly into Supabase `.or()` without sanitization (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The branch system is structurally complete - context provider, CRUD hook, page, selector, migration - but the two user-facing components (BranchSelector, BranchesPage) are wired to inline mock arrays rather than the `useBranches` hook sitting in the same codebase. The context persists a branch ID to localStorage, but since the selector offers fake IDs that won't match Supabase rows, any downstream filtering by `currentBranchId` will return empty results when real data arrives.

The barcode scanner wraps html5-qrcode with proper lifecycle management and exposes a product-lookup page that queries by barcode via Supabase. The `useProductByBarcode` hook disables retries entirely (`retry: false`), which means a single network hiccup surfaces a permanent "Not Found" state until the user rescans.

The PWA layer adds a manifest, placeholder icons, and a service worker with three caching strategies. The service worker is a static file in `public/` - it cannot reference Vite's build manifest, so hashed asset URLs accumulate in the cache indefinitely across deploys with no eviction beyond full cache-name rotation.

The `useBranches` hook constructs Supabase filter strings by interpolating the `search` parameter directly into an `.or()` clause. If search input contains PostgREST filter metacharacters (`.`, `,`, `%`), the query will either break or produce unexpected matches.

## Issues (6)

1. **BranchSelector hardcoded mock data** - Replace `mockBranches` array with `useBranches({ is_active: true })` hook to load real branches from Supabase.
2. **BranchesPage CRUD is non-functional** - Wire `onSubmit`/`confirmDelete` to `useCreateBranch`/`useUpdateBranch`/`useDeleteBranch` mutations and replace mock data table source with `useBranches()` query results.
3. **Search filter injection in useBranches** - Sanitize the `search` parameter before interpolating it into the `.or()` PostgREST filter string; escape `.`, `,`, and `%` characters or use individual `.ilike()` calls.
4. **Service worker cache staleness** - Vite emits content-hashed filenames, but `sw.js` has no mechanism to invalidate its cache when new hashes appear. Consider incrementing `CACHE_NAME` at build time or using a workbox integration that generates a precache manifest.
5. **useProductByBarcode no-retry on transient failure** - `retry: false` means a single network error shows "Product Not Found" permanently. Consider retrying on network errors while skipping retries on 404s.
6. **Branch context not consumed by data hooks** - No existing data hook (products, warehouses) filters by `currentBranchId`, so the selector is cosmetic even if wired to real data. Document or implement the filtering integration.

## Details

### BranchSelector and BranchesPage are mock-only

`BranchSelector` renders a hardcoded `mockBranches` array of five objects. The `useBranches` hook exists in `src/hooks/useBranches.ts`, ready to query Supabase, but is never imported by the selector.

`BranchesPage` duplicates this pattern at larger scale: a six-item mock array feeds the DataTable, and `onSubmit`/`confirmDelete` are empty stubs. The hooks (`useCreateBranch`, `useUpdateBranch`, `useDeleteBranch`) are imported nowhere in the page.

### Supabase filter injection in useBranches

The search filter is built by string interpolation into `.or()`. PostgREST's filter syntax uses `.` as a separator and `,` as an OR delimiter. A search string containing these characters will corrupt the filter expression.

### Service worker cache lifecycle

The service worker uses a single `CACHE_NAME` and caches static assets. For Vite builds with content-hashed filenames, old hashes remain cached indefinitely because no code ever evicts individual entries.

### Misleading delete confirmation in BranchesPage

The migration uses `ON DELETE SET NULL`, but the delete dialog warns "this action will remove all associated data" - the opposite of actual behavior.
